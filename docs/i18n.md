# Localization

User-facing strings live in `i18n/<locale>.json`. Scripts look up a key rather
than printing English directly, so adding a language is adding a file.

## How it works

```sh
. "$(dirname "$0")/lib/i18n.sh"     # sets up t()

t status.paused                      # -> "paused — ingest stopped, brain still queryable"
t ingest.repo_complete my-app 300    # positional args fill %s
```

Locale is taken from `HCB_LOCALE`, falling back to `LANG`, falling back to `en`.
A key missing from the active locale falls back to `en` rather than printing
the raw key, so a partial translation degrades to mixed output instead of
gibberish.

## Adding a language

1. Copy `i18n/en.json` to `i18n/<locale>.json` — use the full code where it
   matters (`pt-BR`, not `pt`).
2. Translate the values. Leave the keys alone.
3. Run `./scripts/check-i18n.sh` to confirm no key is missing and every `%s`
   count matches the English source.

A translation with a different number of `%s` than its English original is a
runtime bug, not a typo, which is why the check is mechanical.

## Rules for strings

**Never concatenate a sentence from fragments.** Word order differs between
languages, and a sentence assembled from three pieces can only be correct in the
language it was assembled for. One key per complete sentence.

```sh
# wrong — unassemblable in languages that put the object first
echo "$(t common.ingested) $count $(t common.commits)"

# right
t ingest.count "$count"
```

**Keep the variable order flexible.** Where a string takes more than one
argument, use `%1$s` / `%2$s` so a translator can reorder them.

**Pluralization is per language, not per count.** Do not branch on `n == 1` in
a script. Provide `.one` / `.other` keys and let the lookup choose; languages
with more than two forms add their own keys in their own file.

**Dates and numbers go through the formatter, never `printf`.** A thousands
separator is a comma in some locales and a full stop in others, and a date
written `03/04` means two different days depending on where it is read.

## What is deliberately not localized

Log lines written to `~/.hindsight/logs/` stay in English. They are diagnostic
output read by whoever is debugging — often a stranger in an issue thread — and
a translated log cannot be searched against this documentation or pasted into a
bug report usefully.

The split is: anything a person is *shown* is localized; anything a person
*debugs with* is not.
